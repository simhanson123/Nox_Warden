집중 범위:
1. 순수 authority_registry 계약의 closed JSON, 필수 nullable 항목, 크기 제한,
   canonical bytes/base64/DSSE PAE, 64-byte Ed25519 서명, 목적/tenant/target/key,
   배타적 만료와 uint64 epoch. asset ID와 revision hash의 정렬 배열을 index로
   암묵 대응하지 않는지, 원본 envelope/delegation/service ID 의미를 보존하는지.
2. Schema15의 독립 trust pin/영구 revocation, 원본 객체/owner proof/authorization/
   pending head/audit의 원자성, 새 9개 table의 rowid/PK/UNIQUE 및 INSERT OR REPLACE
   거절 matrix와 rollback-only positive controls(무관한 FK/제약에서 미리 실패하지
   않는지), exact canonical retained bytes, 실제 old14 migration/backup 전 검증과
   retry/output loss/restart/동시성, retained/current 상태와 shared clock floor.
   다른 연결이 expiry를 관측한 뒤 final transaction에서 되살아나는지 확인하라.
3. 독립 principal/human/public credential pin과 실제 activation/owner WebAuthn,
   exact manifest subject/origin/RP/role/nonce/assertion/proof hash 결합.
   proof hash만으로 owner consent를 만들거나 controller login을 가져오는지.
   현재 한-owner local/Lab 초기 profile과 기존 Team plan 다중인 quorum를
   완전한 Team bootstrap governance로 혼동하지 마라.
4. 실제 fw_signer authorize_bootstrap가 retained manifest ID만 받아 protected
   key와 현재 genuine owner proof를 해결한 뒤 exact DSSE를 발급/보존하는지.
   별도 UID/OS peer credential, private path/권한/키/DB device+inode, 전체 frame의
   monotonic deadline/크기/EOF, key loss/DB replacement/잘못된 UID/재시작/응답유실.
   임의 payload/actor/PASS 입력이나 signer key 노출 경로가 없는지.
5. bootstrap root는 exact independently pinned key hash여야 한다. 새 초기화가
   기존 target epoch/generation/issued/UNKNOWN/quota를 reset하지 못해야 한다.
   local authorization은 authorized_pending_target_confirmation이며 실제 target
   durable epoch/baseline/probe 확인이나 운영 policy grant/dispatch가 아니다.
   management baseline B hash와 full StateIR baseline hash를 구분하라.
6. core grant adapter의 실제 typed payload/signature와 원래 [S,E), full original
   cost, current approval/quota/claim/generation/finalization/replay. private test
   witness를 production resolver와 혼동하지 마라. BUILD_IDENTITY_REQUIRED,
   NATIVE_QUALIFICATION_REQUIRED, TARGET_EPOCH_CONFIRMATION_REQUIRED,
   POLICY_SIGNER_KEY_REQUIRED, WORKLOAD_SOURCE_ATTESTATION_REQUIRED가 빠진 상태에서
   운영 signing/dispatch가 열리는지 검토하라. unsigned delivery는 환급 근거가 아니다.
7. D6a/D6b: inner/outer 검사기 typed U=1/e=0/C=5, deduction6, exact E−8,
   binding wall/monotonic 대응 ±1s, 독립 token minimum과 1ms truncation allowance,
   malformed report의 StageFailure. 실제 packets/captures와 primitive unit 결과를
   구분하고 원래 5s 설치예산/그 안의 2s process reserve/복구기한을 늘리지 마라.
8. 충돌 legacy14 전체 DB refusal은 모든 tenant에 적용된다. 현재15 open의
   MigrationRequired/DATABASE_REJECTED와 explicit migrate의 Binding/
   MIGRATION_REJECTED를 구분하라. 실패로 새 backup이 생겼다고 추론하지 말고,
   원본/기존 backup 보존, 신뢰할 수 있는 compatible authority/generation 복원,
   genuine request/strict review, rollback resurrection/역사편집/issued 환급 금지를
   확인하라. 자동 repair/완전한 운영 restore가 구현됐다고 주장하지 마라.
