# 관측·경로·보안감사 명세

**F-2.0 · 사람과 AI Agent가 같은 증거를 조회하는 계약**

## 1. 대시보드 구성요소

React/TypeScript 정적 UI를 기본으로 한다. 화면을 구성하기 위해 유료 SaaS나 별도 Node 서버를 필수로 두지 않는다. 아래 오픈소스 core를 채택하며 정확한 release/전이 의존성은 M00 lockfile에서 고정한다.

| 구성요소 | 역할 | 확인한 라이선스 |
|---|---|---|
| React Flow / `@xyflow/react` | 경로·target·근거 그래프, 선택·확대·축소 | [MIT](https://github.com/xyflow/xyflow/blob/main/LICENSE) |
| TanStack Table | 정책·자산·감사 목록, 정렬·선택·페이지 처리 | [MIT](https://github.com/TanStack/table/blob/main/LICENSE) |
| Radix Primitives | dialog, menu, tooltip, focus 관리 | [MIT](https://github.com/radix-ui/primitives/blob/main/LICENSE) |
| Recharts | 만료·실패·처리시간 등 집계 차트 | [MIT](https://github.com/recharts/recharts/blob/main/LICENSE) |

우리 프로젝트의 Apache-2.0 선택과 MIT 의존성 사용은 양립할 수 있지만 제3자 copyright/라이선스 고지는 보존한다. 유료 Pro 예제·템플릿·에셋은 이 선택에 포함하지 않는다. 그래프와 차트는 lazy-load하고 첫 화면은 상태 요약과 표를 먼저 표시한다. DOM에 무제한 감사 이벤트를 올리지 않고 서버 pagination과 table virtualization을 사용한다. 그래프는 기본 최대 256 node/512 edge, 범위 초과는 명시적 필터·묶음 보기로 전환한다.

## 2. 세 가지 사실 층

1. **의도:** 승인된 정책과 컴파일된 경로. 이것은 실제 패킷 이동을 증명하지 않는다.
2. **집행 관측:** native backend에서 읽은 rule/generation/hash, 마지막 성공 시각, drift.
3. **통신 관측:** 양성·음성 probe, 실제 flow/counter, 제한된 선택적 패킷 증거. 수집 범위 밖은 unknown이다.

세 층을 서로 다른 선 종류·라벨·시각·증거 링크로 표시한다. route table이나 cloud security group을 읽었다는 이유로 end-to-end 경로를 실측했다고 하지 않는다. 인터넷의 모든 중간 라우터·암호화 payload를 알 수 있다고 약속하지 않는다. observed edge는 `observed_at`, 관측 지점, window, 수집 방식, evidence hash를 가진다. stale/degraded/unknown을 녹색 정상으로 렌더링하지 않는다.

## 3. 전체 과정 추적

요청 상세는 다음 event를 같은 correlation chain으로 제공한다: 요청 수신, 신원/워크로드 결합, 자산/service snapshot, scope/quota 판정, 계획 생성, 의미 검증, 승인/거절, 서명 허가, dispatch, native 적용, readback, positive/negative/new-management probe, confirm, active, expiry/revoke, recovery 및 terminal result.

각 이벤트는 event ID, request/plan/operation/target ID 중 해당 값, server UTC, target UTC와 clock uncertainty, actor/worker, stage/state, canonical object hash, predecessor reference, code와 evidence reference를 포함한다. 사용자가 보기 좋은 설명은 이 기계 필드를 번역한 파생값이다. AI 요약은 원문 증거와 분리하고 model/version/생성시각을 표시한다. 원본 승인 사유를 AI 설명으로 덮어쓰지 않는다.

timeline은 operation의 상태 전이만 보여주는 카드가 아니라 실패·재시도·UNKNOWN·중복 제거를 보존한다. 똑같은 operation의 재전송은 event ID로 멱등 처리하며, 다른 worker attempt는 attempt ID/claim generation으로 구별한다. 여러 target을 한 원자 작업으로 표현하지 않는다.

## 4. 화면의 조사 흐름

Overview → OS별 target health → target detail → topology/정책 diff → operation timeline → exact plan/approval/grant/receipt → evidence download 순서가 3회 이내 핵심 클릭으로 이어지도록 설계한다. 특정 패킷 판정 조사에서는 family/protocol/source/destination/interface/time를 입력해 reference evaluator의 예상 판정과 당시 snapshot을 확인한다. 이 결과에는 simulation 표시를 붙인다.

경로 node를 선택하면 asset revision, workload binding의 근거·만료, scope, target capability, 실제 last seen을 보여준다. edge를 선택하면 허용·차단 근거 policy ID, expiry/review_at, 겹치는 유효 allow, deny 우선 이유와 관측 결과를 보여준다. 부모 정책·승인 변경이 필요한 동작은 새로운 plan으로만 진행한다. 드래그로 선을 그었다는 이유로 방화벽을 즉시 열지 않는다.

모든 그래프에는 같은 정보를 가진 표·텍스트 경로 표현과 JSON 다운로드가 있다. 색상만으로 verdict를 구별하지 않는다. 작은 화면·키보드·화면낭독기에서도 ID/상태/근거를 읽을 수 있어야 한다. 기본 audit 화면은 읽기 권한만 필요하다. 토큰/secret/raw prompt는 표시하지 않는다.

## 5. AI Agent 및 자동 감사

기존 core MCP 6개 도구의 의미는 유지한다. 감사 확장은 별도 읽기 권한으로 아래 REST API를 호출하는 read-only tool/resource로 구현한다. 쓰기·승인·trust store 변경을 감사 tool에 숨겨 넣지 않는다.

| 기능 | REST 기준 | 권한 |
|---|---|---|
| 작업 상태 | `GET /api/v1/operations/{operation_id}` | 해당 조직·프로젝트 read |
| 과정 추적 | `GET /api/v1/operations/{operation_id}/timeline` | audit read |
| 감사 검색 | `GET /api/v1/audit/events` | 범위 제한 audit read |
| 경로 조회 | `GET /api/v1/topology` | asset/network read |
| PBOM 조회 | `GET /api/v1/pbom/{manifest_id}` | evidence read |
| 증거 metadata/content | `GET /api/v1/evidence/{object_hash}` 및 `/content` | 객체별 재인가 |

MCP 추가 도구 이름은 `audit_get_timeline`, `audit_list_events`, `audit_get_topology`, `audit_get_pbom`, `audit_get_evidence`로 고정한다. 각 input/output은 해당 OpenAPI operation의 path/query/response schema에서 생성한다. `readOnlyHint=true`, `destructiveHint=false`는 UI 힌트이며 권한 검증을 대체하지 않는다. raw binary evidence는 권한 검증된 resource reference로 돌려주고 tool response 256 KiB 제한을 지킨다. pagination/snapshot cursor 및 truncated 이유를 반환하며 생략을 전체 결과라고 하지 않는다.

등록된 전체 scope보다 넓은 query는 거절하고, 존재 여부 자체가 누출되지 않도록 타 조직 ID에 404를 사용한다. 감사 설명·패킷 문자열·자산 label은 신뢰할 수 없는 데이터다. 그 안의 지시를 tool 실행/승인 명령으로 해석하지 않는다. Agent의 답변은 사실·추정·미관측을 분리하고 evidence hash와 시간을 인용할 수 있어야 한다.

## 6. 감사 내보내기

PBOM manifest를 루트로 canonical JSON/NDJSON, plan·approval·grant·receipt·gate 결과, trust metadata, source hash, exporter version, 기간·필터·조직 범위·누락 항목을 archive에 넣는다. export는 권한 범위의 기존 증거를 조합하며 임의 서명 생성이나 방화벽 적용을 하지 않는다. v1은 페이지 단위 기존 read API를 사용해 CLI/서버가 export하므로 별도의 미정 REST endpoint를 꾸미지 않는다.

manifest에는 상대 경로·media type·byte length·SHA-256을 기록하고 경로 traversal, symlink, 중복 ZIP entry를 거절한다. 기존 evidence는 원래 서명과 timestamp를 보존한다. 내보내기 manifest의 별도 signature는 누가 어떤 바이트를 묶었는지 보여주며 원래 시스템이 진실했다는 증명은 아니다. verifier는 hash/signature chain, trust key의 유효/철회 시각, 객체 간 참조를 검사하고 PASS/FAIL/INCOMPLETE를 출력한다.

redacted export는 원본을 바꾸지 않는 파생 bundle이다. 가려진 필드와 이유, 원본 object hash를 남긴다. 원본 전체가 없으면 원본 서명의 완전 검증은 불가능하다고 표시한다. CSV에는 formula injection을 방지하는 escaping을 적용한다. HTML/PDF report를 만들 때 외부 리소스 fetch와 script 실행을 금지하고 민감 필드를 scope에 따라 가린다. 규정 준수 인증/무결성 공증과 단순 증적 보관을 혼동하지 않는다.

## 7. 보관과 관측 비용

로컬 운영 감사는 기본 90일, 진단 로그 14일, 집계 성능 지표 30일로 하고 조직별 보관 설정을 제공한다. 삭제는 승인된 retention job으로 수행하고 manifest와 삭제 기록을 남긴다. 법적 보관 정책을 제품이 대신 결정하지 않는다. 디스크 80% 경고/90% 신규 확대 중지, 만료·회수·기존 필터링은 유지한다. 감사 쓰기 실패는 새로운 권한 확대의 성공으로 숨기지 않는다.

full packet capture는 기본 OFF이며 저장 위치·scope·시간·상한을 명시한 별도 운영 동작이다. 기본 감사에는 payload가 필요하지 않다. 제품 통계 서버로 감사 데이터가 보내지지 않는다. 로컬 로그/메트릭과 F_06의 선택적 사용 통계를 명확히 분리한다.
