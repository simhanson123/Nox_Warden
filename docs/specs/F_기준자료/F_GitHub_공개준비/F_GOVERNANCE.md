# 거버넌스

설계 기준판 1.0 | 2026-10-30

이 문서는 프로젝트가 채택할 운영 규칙이다. 실제로 존재하지 않는 유지보수자·독립 보안팀·후원 조직을 구성한 것으로 표시하지 않는다. 현재 패키지는 설계와 공개 준비 자료이며 운영 제품의 릴리스 이력은 없다.

## 역할과 책임

| 역할 | 책임 | 제한 |
|---|---|---|
| 저장소 관리자 | 접근 권한·브랜치 보호·제보 경로·유지보수자 지정 | 계정 소유가 모든 기여의 저작권 소유를 의미하지 않음 |
| 유지보수자 | 변경 검토·이슈 분류·ADR·문서·릴리스 검수 | 검수 없이 안전성·지원 범위를 확대하지 않음 |
| 구성요소 담당자 | 어댑터·스키마·컴파일러 등 담당 범위 관리 | 실제 시험하지 않은 버전·장비를 지원으로 표시하지 않음 |
| 기여자 | 권리를 가진 변경 제출·검수·DCO | 병합·릴리스 권한은 별도 부여 |
| 릴리스 담당자 | 승인된 커밋·배포물·SBOM·고지·서명 확인 | 코드 검토와 릴리스 서명을 혼동하지 않음 |

처음에는 한 사람이 여러 역할을 맡을 수 있다. 1인 운영 사실과 이해상충을 기록하고 자기 검토를 독립 검토로 표시하지 않는다. 독립 검토자를 확보하지 못한 보안 핵심 변경은 그 상태를 릴리스 노트에 명시하며, 안정판 승격의 독립 검토 요건을 충족한 것으로 처리하지 않는다.

## 의사결정

일반 변경은 PR에서 근거와 검수 결과를 검토한다. 정책 의미, AI 권한, 인증·서명, 만료·복구, 감사 증적, 호환성, 라이선스, 운영 지원 범위는 ADR를 작성한다. ADR에는 문제, 결정, 대안, 선택 이유, 제약, 검수 조건, 재검토 조건을 담는다.

의견이 충돌하면 재현 가능한 증거와 명시된 안전 계약을 우선한다. 결정자와 반대 의견, 남은 위험을 기록한다. 수치 점수나 모델의 합의만으로 변경을 승인하지 않는다. 해결되지 않은 안전 계약 위반을 “알려진 제약” 한 줄로 숨겨 안정판에 포함하지 않는다.

기본 검토 목표는 일반 변경 1명, 권한·서명·정책 집행·라이선스 경계 변경 2명의 독립된 인간 검토다. 확보한 인원이 적으면 가능한 검토 수를 정확히 표시하고, 실험판·설계판 상태를 유지한다. 자동 검사와 AI 검토는 인간의 독립된 판단을 보완한다.

## 유지보수자 지정과 권한

반복적으로 정확한 검수·문서·사용자 지원을 제공한 기여자에게 필요한 범위의 권한을 부여한다. GitHub 계정과 담당 범위, 지정·해제 근거를 공개 기록에 남긴다. 특정인을 이 패키지에서 임의로 지정하지 않는다.

관리·릴리스 계정에는 다중요소 인증과 최소 권한을 적용한다. 개인 토큰을 공유하지 않으며 자동화에는 목적별 짧은 수명 자격증명을 사용한다. 장기간 부재·이해상충·권한 오용이 있으면 다른 관리자가 필요한 접근을 회수하고 근거를 기록한다. 관리자가 한 명뿐이면 신뢰할 수 있는 후속 관리자를 확보할 때까지 단일 책임 지점을 명시한다.

## 보안·릴리스

보안 제보는 SECURITY에 따른다. 처리 인원은 필요한 사람으로 제한하고 영향 범위·완화·수정·공개 시점을 기록한다. 제보자의 식별정보는 동의 범위에서 공개한다.

설계판, 실험판, 안정판을 구분한다. 릴리스 승인에는 기능 검수, 실패·복구 시험, 지원 매트릭스, 라이선스·고지·대응 소스, 재현 가능한 빌드 정보, 서명·체크섬이 필요하다. 패킷 처리가 구현되지 않은 패키지를 실행 제품으로 발표하지 않는다.

지원 기간·응답 목표는 실제 유지보수 능력에 맞춰 공개한다. 무료 공개를 근거로 제공하지 못할 SLA나 보증을 약속하지 않는다. 유료 지원·호스팅 계약은 오픈소스 라이선스와 구분한다.

## 기여 권리·재원·브랜드

기여자는 자신의 권리를 유지하고 대상 파일의 라이선스로 기여한다. 프로젝트 관리자에게 저작권이 자동 이전되지 않는다. 기본은 Apache-2.0이며 제3자·eBPF 예외는 파일별로 명시한다.

후원·유료 지원을 받아도 안전 기능의 검수 기준과 취약점 처리 원칙은 동일하게 적용한다. 재원이 의사결정에 영향을 주는 경우 관계를 공개한다. 후원자를 공식 보안 인증자로 표시하지 않는다.

이름·로고는 실제 권리자와 이름 충돌 검토 후 사용 정책을 정한다. 이 문서만으로 상표 등록이나 독점권이 생겼다고 주장하지 않는다. 외부 회사·제품과의 공식 제휴를 암시하지 않는다.

## 규칙 변경

거버넌스 변경은 일반 PR과 ADR로 제안하고 변경 이유·영향을 공개한다. 기여자의 기존 권리를 소급 박탈하거나 이미 부여된 제3자 라이선스를 임의로 취소하지 않는다. 예외에는 담당자·기간·종료 조건을 기록한다.
