# F_04 정책 컴파일러·집행·복구 개발 명세

**규격 F-2.0 · 구현 의무를 정의하는 명세 · 제품 구현/운영 검증 완료 선언 아님**

이 문서는 개발자가 정책을 커널 규칙으로 바꾸고, 실패한 적용을 관측·복구하는 코드를 작성할 때의 기준이다. F-1.0 최종설계와 기존 `F_개발계약`은 입력 근거로 보존한다. 기존 `f.plan/v1`, `f.grant/v1`, `change_kind=add_access_lease`의 의미를 변경하지 않는다. F-2.0의 추가 객체와 세부 의미는 이 개발명세 패키지의 API·데이터 계약 및 신규 스키마를 따른다. 세부 명세·스키마·fixture가 충돌하면 같은 PR에서 정합성을 고치기 전 병합/출시하지 않는다.

모듈은 `fw_domain`, `fw_validator`, `fw_compiler_nft`, `fw_agent`, `fw_enforcer`, `fw_release`처럼 중립적인 기술 이름을 쓴다. 프로젝트의 공개 이름을 여기서 확정하지 않는다.

## 1. 지원 단위와 완료 범위

제품의 필수 플랫폼은 **Linux, Windows Server, macOS의 호스트 방화벽**이다. 공통 프로필 이름은 `common-host-v1`이며 로컬 시작·종료 트래픽의 INPUT/OUTPUT 의미를 제공한다. Linux의 두 인터페이스 라우터는 추가 프로필 `linux-routed-v1`이다. 모든 OS가 라우터·NAT·VPN 기능까지 제공한다는 뜻이 아니다.

위 이름은 qualification profile이다. 기존 wire `profile` enum은 `lab`, `host`, `routed_gateway`를 유지한다. `host`는 플랫폼별 `common-host-v1`, Linux의 `routed_gateway`는 `linux-routed-v1` qualification으로 매핑한다. `lab`은 해당 실습 topology의 capability/qualification을 명시해야 하며 운영지원 등급을 뜻하지 않는다. 이 이름을 바꾸어 기존 wire schema와 hash를 변경하지 않는다.

| backend | 구현 경계 | 필수 조건 |
|---|---|---|
| Linux nft | 전용 inet table, 구조화 nft JSON, 로컬 enforcer | 이 문서의 strict-current-union, 커널 timeout, 원자 전환, read-back |
| Windows WFP | 자체 provider/sublayer/filter 및 서명된 kernel callout | F_09의 per-packet 인가, 기존 세션 재평가, 수명·boot guard; ALE 연결 승인만으로 대체 불가 |
| macOS Network Extension | NEFilterPacketProvider system extension, 필요한 data-provider 보조 | F_09의 entitlement·서명·배포·중단 시 동작 검수; PF를 배포 제품 backend로 쓰지 않음 |

공통 의미를 만족하지 못하는 adapter는 해당 capability를 거절하고 `designed` 또는 `implemented`에 머문다. Linux 시험 통과만으로 세 OS 제품을 완료 처리하지 않는다. macOS extension 장애 시 실제 fail-close 여부와 Windows callout 로드 전후의 보호 공백은 필수 인수시험 대상이다. OS별 세부 정본은 `F_09_멀티플랫폼_설치_집행_명세.md`를 따른다.

## 2. backend 공통 인터페이스

아래는 언어 내부 인터페이스이며 사용자에게 자유 형식 native 명령을 받는 API가 아니다.

| 연산 | 입력 | 출력/불변조건 |
|---|---|---|
| `inspect_capabilities` | 설치 프로필, OS build, scope | 서명 가능한 capability snapshot. 지원하지 않는 항목을 자동 추정하지 않음 |
| `compile` | CanonicalStateIR, CapabilitySnapshot, compiler version | PortableArtifact, RuleOriginMap, 검증 의무. 네트워크/시각/난수 조회 금지 |
| `prepare` | 검증된 grant, artifact, 신뢰 시각 표본, actual state | journal entry, InstallationManifest, armed watchdog. 업무 권한을 아직 활성화하지 않음 |
| `commit` | prepared operation과 로컬 fencing token | 원자 전환 결과 또는 UNKNOWN. 응답 유실을 미적용으로 해석하지 않음 |
| `read_back` | scope, expected artifact, 관측 deadline | 실제 구조·수명 검사, raw snapshot hash, semantic state 결과 |
| `confirm` | operation/generation에 결합한 서명된 확인 | durable 확정 또는 이미 복구된 결과. 늦은 확인으로 복구를 취소하지 않음 |
| `revoke` | 인증·서명된 대상 lease/revision 회수 명령 | tombstone durable → 해당 권한 제거 → 관측 receipt |
| `recover` | journal, 현 커널 상태, 제한된 recovery authority | 제한 projection 또는 quarantine. 권한 확대 추측 금지 |

오류는 `Invalid`, `Unsupported`, `Stale`, `Conflict`, `Replay`, `ClockUntrusted`, `BudgetExceeded`, `Unknown`, `Degraded`를 구별한다. compiler가 `Unsupported`를 반환하면 더 넓은 규칙으로 fallback하지 않는다. backend 완료 상태는 실제 receipt로 결정하고, controller의 queue ACK는 집행 성공이 아니다.

공통 `atomic_apply`는 인가 decision image의 세대 전환을 뜻하며 OS API 전체가 하나의 transaction이라는 주장이 아니다. Linux의 단일 nft batch와 달리 Windows의 filter/image 전환은 F_09의 제한 guard 단계를 거친다. publish 전 중간 허용은 old/new 허용 집합의 교집합 이내로 제한하고 publish 뒤에는 candidate를 넘지 않아야 한다. 그 사이 필요한 통신이 잠깐 차단될 수 있음을 deployment impact에 표시한다. 여러 layer를 old/new 한 번에 바꾸었다는 증거가 없는데 이를 전체 원자 교체라고 기록하지 않는다.

capability는 최소 OS/build/architecture/backend version, profile, IP family, TCP/UDP/ICMP subset, 원자 전환 범위, existing-flow 재평가, independent expiry, reboot guard, crash fail-close, deadline guard, evidence level을 표현한다. `strict_expiry=true` 하나로 세부 조건을 감추지 않는다. 신규 필드의 정확한 wire 구조는 패키지의 확장 스키마에 고정한다.

## 3. 정본 상태와 해시

### 3.1 CanonicalStateIR

StateIR는 해당 target·enforcement scope의 전체 승인된 프로그램이다. 요청 patch가 아니다. 다음 값이 필요하다.

- org/project/target/scope ID, 프로필, IP families, namespace identity, conntrack zone.
- 관리 baseline의 revision/hash와 구체 flow, anti-spoof source-interface bindings, host-local addresses, 고정 route/interface snapshot.
- 설치 대상으로 승인된 정책 revision의 완전한 목록, action/scope/절대 lifetime, revision과 lease/권한 객체의 대응.
- policy/lease tombstone의 revision·권한 근거·관측 순서. tombstone을 적용한 실효 정책 목록.
- capability, source asset/service/binding snapshot, normalization/semantic/compiler contract versions.

wire `StateIR`에 위 값을 모두 중복 필드로 추가하지 않는다. `management_baseline_hash`는 B·anti-spoof·scope/namespace·zone·route/interface 설정의 검증된 객체에, `source_snapshot_hash`는 org/project/asset/service/binding 상태에, `target_capability_hash`는 실제 backend/profile에 결합한다. 이 참조 대상 bytes를 artifact bundle에 함께 제공하고 hash/조직/target 결합을 검증한다. 해시 문자열만 존재하는 unresolved 참조는 컴파일 불가다. semantic/compiler contract version은 portable artifact와 plan의 compiler/validator digest에 고정한다.

스케줄러에 대기 중인 미래 요청은 현재 target에 설치된 프로그램으로 가장하지 않는다. 그 요청은 시작 시각에 다시 계획·승인을 확인하고 새 grant를 얻는다. 기존 프로그램에 이미 들어 있던 절대 종료 시각은 시간 경과나 재시도로 변경하지 않는다.

`desired_state_hash`는 정규화한 전체 StateIR의 의미 fingerprint다. `baseline_hash`는 계획 수립 시 기대했던 전체 managed state의 fingerprint이며, 관리 예외 B만의 hash와 구별한다. B의 hash는 StateIR 내부에도 별도로 둔다. policy order를 정렬하고 runtime counter, nft handle, 남은 milliseconds, 관측 시각은 이 hash에 넣지 않는다. 정책 ID·revision·원래 절대 만료·tombstone은 넣는다. 자연 만료로 이 정본 hash를 매초 바꾸지 않는다.

### 3.2 portable artifact와 실제 설치물

`artifact_hash`는 고정된 PortableArtifact의 canonical bytes다. artifact에는 정규화 rules/template, 절대 deadline, token ownership, compiler/binding algorithm digest, 제한 resource counts가 들어간다. 배포 시점의 상대 TTL을 hash 안에 미리 고정하지 않는다.

agent는 artifact를 해석하면서 오직 승인된 binding 알고리즘으로 현재 잔여 TTL을 줄인다. 그 결과인 `InstallationManifest`에는 grant/artifact/state hashes, 표본 UTC/monotonic/boot identity, uncertainty, 각 token의 실제 TTL·절대 cutoff, 생성한 nft JSON의 hash, compiler binding version을 남긴다. 이 runtime hash를 `artifact_hash` 대신 사용하거나 서명된 artifact를 몰래 수정하지 않는다. signer/enforcer는 상대 TTL이 원래 권한을 확장하지 않는지 독립 검증한다.

read-back의 `observed_state_hash=desired_state_hash`는 source 파일을 다시 hash했다는 뜻이 아니다. 실제 구조가 기대한 artifact와 대응하고, 토큰·deadline·tombstone·baseline 검사까지 통과했음을 뜻한다. raw kernel dump hash와 검사 report hash를 별도로 receipt에 남긴다. 검사하지 못한 표현식이 하나라도 있으면 동등하다고 표시하지 않는다.

기존 `f.receipt/v1`에 알 수 없는 필드를 추가하지 않는다. InstallationManifest·native read-back dump/report는 receipt ID/hash에 PBOM 간선으로 연결되는 별도 evidence 객체로 남긴다. 신규 확장 스키마의 해당 객체를 사용하며, artifact/manifest/readback의 완전한 wire schema·정상/반례 fixture는 runtime M0의 필수 산출물이다. 문서에 적은 객체 이름만으로 schema가 제공된 것으로 처리하지 않는다.

## 4. patch 합성과 결정적 컴파일 순서

1. schema/크기/중복 JSON key와 도메인 생성자 검증을 수행한다.
2. target/org/project, workload·asset·service snapshot 및 정책 lifetime를 확인한다.
3. 실제 managed baseline의 전체 정책 목록을 불러오고 기대 hash와 대조한다.
4. `add_access_lease`는 새 allow revision만 추가한다. 기존 deny, 다른 lease, baseline B는 보존한다. 같은 ID의 다른 revision을 은밀히 replace하지 않는다.
5. 일반 `policy_change`는 확장 스키마의 tagged operations만 적용한다. `add_deny`, `replace_policy`, `remove_policy`는 expected revision/hash를 비교한다. deny 제거·축소 및 allow 확대는 Δ+를 만들 수 있다. baseline 변경은 일반 정책 변경으로 실행하지 않는다.
6. tombstone을 적용한다. 같은 lease의 폐기된 revision은 재전송·rollback·DB restore로 되살리지 않는다. 갱신은 새 lease와 새 승인으로 실행한다.
7. CIDR/port/interface/family/protocol/time를 정규화한다. direction별 빈 인터페이스 배열의 의미를 엄격히 검사한다. input은 ingress만, output은 egress만, forward는 둘 다 필요하다.
8. 참조 평가기로 모든 시간 분할의 Δ+·Δ-·protected-flow 영향을 산출한다. `review_at`은 deny 삭제 경계가 아니다. 분석 예산 초과는 UNKNOWN이다.
9. family/direction/protocol별 RuleIR를 만들고 deny와 allow를 구분하여 내린다. 원본 policy revision → native rule/set/branch의 RuleOriginMap을 생성한다.
10. static 검사로 무제한 accept, established blanket accept, 사용자 명령, 무소유 객체, deadline 없는 임시 branch가 없는지 확인한다.
11. canonical nft JSON template와 read-back 기대식을 생성한다. 같은 입력·compiler version이면 byte-identical이다.
12. 고정 fixture conformance와 target capability를 확인한다. target에서 `nft --check`를 실행해도 의미·연결성 검증이 완료되는 것은 아니다.

출력 상한은 처음에는 전체 정책 1,000개, 요청 patch 256개, 생성 rules 50,000개, sets 10,000개, artifact 16 MiB로 둔다. 기준은 admission limit이며 처리 성능 보장이 아니다. 상한을 늘리는 PR은 메모리·compile/apply 시간·rollback 크기 시험을 포함한다. Cartesian expansion을 먼저 전부 할당한 뒤 크기를 검사하지 않는다.

## 5. 참조 evaluator와 흐름 정의

업무 허용은 `P(t)=union(valid allow at t) - union(active deny at t)`다. 별도 보호 baseline B는 업무 P에 섞지 않는다. 평가는 최초 요청 방향의 family, source/destination, L4 protocol, destination port 또는 ICMP request type/code, 정·역 인터페이스, target/zone을 사용한다.

`evaluate(state, flow, time, observation_context)`는 `Allow(policy_revision_ids)`, `Deny(deny_revision_ids)`, `DefaultDrop`, `Baseline(baseline_rule_id)`, `Invalid(reason)` 중 하나를 반환한다. 테스트 전용 clock/context도 입력으로 전달하고 전역 시계에 의존하지 않는다. 설명용 matching policy 목록은 권한 계산과 같은 함수에서 얻는다.

TCP/UDP의 세션 키는 zone + family + original source/destination + original source/destination ports + protocol이다. 정책은 source port 제한을 두지 않더라도 세션 식별에서 source port를 없애지 않는다. 같은 숫자 포트의 TCP와 UDP는 다르다. API principal은 이 세션 키의 프로세스 신원이라고 주장하지 않는다.

기존 세션도 현재 P(t)를 매 패킷 검사한다. A와 B가 동일 흐름을 허용하면 A 만료/반납 후 B가 살아 있는 동안 흐름을 허용한다. 기존 연결의 소유 lease를 한 개만 지정하여 B의 권한을 무시하지 않는다. address shrink와 deny 추가는 새 kernel transaction이 효력을 얻는 시점부터 기존 연결에도 적용한다.

## 6. Linux nft table과 실제 분기

### 6.1 설치 scope와 순서

전용 `inet fw_<scope digest>` table 하나를 사용한다. digest 축약 이름 충돌은 등록 시 검사한다. host와 routed scope가 같은 namespace의 동일 hook을 중복 소유하지 않는다. input/output/forward base chain의 filter priority는 profile에 고정하고, unknown 타 manager가 같은 경로를 관리하면 observe-only에서 멈춘다. 허용 verdict 뒤 다른 hook의 drop 가능성도 preflight/probe로 확인한다.

base chain policy는 `drop`이다. forward를 지원하지 않는 host 프로필은 forwarding을 활성화하지 않는다. 라우터는 좁은 baseline과 default-drop chain이 설치·검증된 뒤 IP forwarding을 활성화한다. `flush ruleset`, `dormant` table, enforcer 종료 시 사라지는 ephemeral owner table로 보호를 구현하지 않는다.

분기 순서는 다음과 같다.

```text
packet parse / anti-spoof / invalid conditions
  -> 명시 baseline B (해당 인터페이스·방향·주소·protocol·port만)
  -> 현재 업무 deny 검사 (original 및 reply/관련 오류의 부모 흐름)
  -> 각 allow revision의 시간·활성토큰·현재 scope 검사
  -> 제한된 drop log/counter
  -> default drop
```

validity 검사를 baseline보다 앞에 두되, NDP/DAD처럼 일반 conntrack state와 다른 정상 제어 트래픽은 별도 좁은 branch로 정의한다. `untracked 전체 drop`을 먼저 둬 IPv6 시작을 깨뜨린 후 `icmpv6 accept`를 추가하는 구현은 금지한다.

### 6.2 allow 활성 토큰의 구체 표현

각 allow revision은 전용 singleton timeout set `fw_live_<revision digest>`를 가진다. set의 key type은 `inet_proto`이며 element는 그 정책의 원본 L4 protocol 번호(예: TCP 6, UDP 17, ICMP 1, ICMPv6 58) 하나다. native JSON의 datatype/timeout 표현을 capability fixture로 확인한다. policy마다 별도 set이므로 같은 protocol의 다른 lease가 수명을 공유하지 않는다. 임의 mark를 강제로 덮는 fallback은 금지한다.

모든 해당 allow branch는 `ct original protocol ∈ fw_live_revision` predicate와 절대 deadline predicate를 포함한다. family와 전체 tuple/scope 검사는 이 token과 별도로 항상 실행한다. 관련 ICMP 오류 branch에서는 kernel이 연관한 부모 conntrack의 원본 protocol을 쓴다. 연관이 없으면 match하지 않는다. set membership 실패는 해당 rule 불일치이므로 다음 allow branch를 평가한다. 그 자리에서 drop/return-to-drop하지 않는다. set timeout을 packet hit로 refresh하는 `update` 동작은 없다. expired element의 GC 지연은 허용 지연이 아니다.

deny에는 종료 timeout set을 만들지 않는다. 검토기한이 지난 deny도 유지한다. 예정 deny 역시 시작 시점의 새 grant 없이 몰래 활성화하지 않는다.

### 6.3 TCP/UDP lowering

L4 의미 확인은 IPv6 확장 헤더를 무시하는 `ip6 nexthdr` 단독 비교로 하지 않고 `meta l4proto`와 지원되는 transport parser를 사용한다. NAT/자동 helper/flowtable/offload는 이 프로필에서 금지한다.

| branch | 필수 검사 | verdict |
|---|---|---|
| original TCP NEW | 실제 request hook, 원본 주소/port/protocol, 정방향 interface pair, ct zone, SYN=1 및 ACK/FIN/RST=0, token/deadline | accept |
| original TCP 후속 | ct direction original, 적절한 tracked state, ct original tuple와 현재 scope, 정방향 pair, token/deadline | accept |
| reply TCP | ct direction reply, established 상태, ct original tuple의 현재 scope, 역방향 interface pair, token/deadline | accept |
| original UDP | tracked NEW/ESTABLISHED, original tuple와 현재 scope, 정방향 pair, token/deadline | accept |
| reply UDP | ct direction reply, established 상태, original tuple와 현재 scope, 역방향 pair, token/deadline | accept |

원본 tuple의 주소는 `ct original ip/ip6 saddr/daddr`, protocol은 `ct original protocol`, port는 TCP/UDP임을 확인한 다음 `ct original proto-dst`로 검사한다. ct tuple이 없는 데이터를 ANY나 port 0으로 바꾸지 않는다. 비대칭 경로로 역방향 pair가 달라지면 지원하지 않은 경로로 차단한다.

input 요청의 응답은 output hook에서 원래 ingress가 현재 egress인지 확인한다. output 요청의 응답은 input hook에서 원래 egress가 현재 ingress인지 확인한다. forward는 두 인터페이스의 역쌍을 확인한다. `input` 정책을 reply output의 새 outbound 권한으로 복제하지 않는다.

TCP loose pickup은 지원 namespace에서 비활성화하고 `nf_conntrack_tcp_loose=0`, checksum validation, liberal mode 관련 실제 값과 영향 범위를 receipt에 남긴다. 이미 타 서비스가 사용하는 host 전체 sysctl을 승인 없이 바꾸지 않는다. 필요한 설정을 독립 scope로 확보할 수 없으면 capability가 불충족이다. 운영 conntrack 전체 flush는 금지한다. 신규 설치 전에 존재하던 연결을 무조건 보존하는 migration은 제공하지 않는다.

deny는 동일 original tuple 기준으로 original/reply 모두 검사한다. 업무 deny가 baseline B를 덮어쓰게 만들지 않는다. 보호된 B와 겹치는 변경은 계획에서 거절한다. 원래 허용 A가 만료된 상태라도 deny를 생략하지 않고 현재 전체 D를 유지한다.

### 6.4 connection marks

F-2.0 기본 compiler는 ct mark를 인가 캐시로 쓰지 않는다. 사용자/타 서비스가 넣은 mark·label은 허용 근거가 아니다. 후속 최적화는 revision/epoch/scope와 current deny·현재 TTL·원자 invalidate를 모두 보존해야 한다. cache hit에서 A의 죽은 권한만 보거나 cache miss에서 B 재평가를 생략하는 최적화는 실패다. 권한 cache와 로그 상관 ID는 구별한다.

## 7. ICMP·NDP·fragment 계약

### 7.1 직접 요청과 응답

core 임시 ICMP 접근은 IPv4 echo-request type 8/code 0 → reply type 0/code 0, IPv6 echo-request type 128/code 0 → reply type 129/code 0을 우선 구현한다. 다른 type/code가 schema상 표현 가능해도 backend capability에 없으면 거절한다. ICMP type을 service port처럼 비교하지 않는다. echo reply는 tracked original request와 direction/type 대응, 현재 allow union/deny와 같은 token/deadline에 묶는다. unsolicited reply는 default drop이다.

### 7.2 관련 오류

`ct state related accept`는 없다. 허용할 오류는 IPv4 destination-unreachable의 지원 code(특히 fragmentation-needed 3/4), time-exceeded, parameter-problem 및 IPv6 destination-unreachable, packet-too-big 2/0, time-exceeded, parameter-problem의 검수된 subset이다. redirect와 obsolete source-quench를 여기에 섞지 않는다.

오류 packet의 outer protocol/type/code를 검사하고, kernel이 인식한 parent conntrack original tuple을 대상으로 **부모 업무 흐름의 현재 P(t)**를 다시 계산한다. 부모 deny나 모든 allow 만료 시 오류도 통과시키지 않는다. helper에 의해 생긴 임의 RELATED data connection은 해당 branch에 맞지 않아 drop된다. forged/truncated embedded tuple, ICMP checksum 실패, association 없음은 drop이다.

원격 라우터가 보내는 오류의 outer source는 원래 목적지와 다를 수 있다. 따라서 outer source=original destination을 무조건 요구하지 않는다. 대신 실제 incoming/outgoing interface 관계, parent tuple, outer destination, source sanity를 검사한다. ICMP 오류가 정상 경로의 중간 router에서 왔다는 사실을 암호학적으로 증명한다고 주장하지 않는다.

gateway가 로컬 생성하는 오류는 OUTPUT에서 parent FORWARD의 원래 두 인터페이스를 모두 직접 읽을 수 없다. 이를 위해 `linux-routed-v1`은 signed `unique-path-binding`을 요구한다. source prefix→ingress가 유일하고 destination route→egress가 고정이며, 관련 오류의 egress가 원래 ingress와 일치해야 한다. route/interface가 바뀌면 drift로 새 쓰기를 중지한다. 이 관계를 증명하지 못하는 topology에서 local-related-error branch를 넓게 허용하지 말고 해당 routed capability를 거절한다. PMTU가 깨지는 상태를 정상 지원이라고 표시하지 않는다.

### 7.3 링크 제어 baseline

NDP는 인터페이스별 link-local/link 범위, hop limit 255, type/code를 검사한다. NS/NA와 DAD의 `::` source·solicited-node multicast 예외를 별도 정의한다. DAD source 예외를 일반 업무 source-spoof 허용으로 재사용하지 않는다. RA/RS는 router/host 역할에 맞춰 승인된 router 주소·인터페이스만 허용한다. 기본 static lab에는 RA/DHCP를 자동 활성화하지 않는다. DHCPv4/v6가 필요하면 정확한 client/server port·주소·인터페이스의 별도 baseline profile을 승인한다.

NDP fragment는 거절한다. 업무 fragmentation은 conntrack defragmentation 이후 완전한 L4 판정이 되는 경로만 지원한다. out-of-order/overlapping/tiny fragment, IPv6 extension chain, atomic fragment를 실제 kernel 시험에 포함한다. 해석할 수 없는 header·없는 port를 ANY로 바꾸지 않는다. reassembly resource exhaustion은 drop/계측/경보로 처리하며 default allow로 fallback하지 않는다.

## 8. 시간·TTL의 수학적 계약

`expires_at`은 권한이 남아 있을 수 있는 최종 UTC 상한이다. 구간은 `[not_before, expires_at)`이다. 시각 오차가 있으면 가용성을 보수적으로 줄일 수 있지만 상한을 늘릴 수 없다. exact clock 모델의 evaluator는 정확한 union을 비교하고, 오차 모델은 no-overpermit와 명시된 early-cutoff bound를 별도로 검사한다.

prepare 표본의 UTC 추정값을 W, 그때의 monotonic을 M, 그 구간의 보장된 UTC 오차 상한을 U라 한다. 실제 submit까지 monotonic 경과 d와 최대 commit 지연 예산 J를 감산한다. token TTL은 `floor_to_kernel_unit(max(0, E - (W + U + d) - J))`다. E는 policy/envelope/delegation/binding의 가장 이른 종료 상한이다. 0 이하이면 element를 넣지 않고 만료로 처리한다. 생략하거나 timeout 0을 무기한으로 해석하는 코드가 없어야 한다.

relative timeout만으로는 지연된 kernel commit의 시작점을 제한하기 어렵다. F-2.0 Linux backend는 모든 allow branch에 **절대 UTC 상한 predicate도 AND**한다. `meta time < cutoff`이며 cutoff는 E에서 승인된 clock-error budget을 보수적으로 뺀 숫자 UTC 값이다. future activation에는 `now ≥ not_before` 검증도 필요하며, 아직 시작하지 않은 계획은 설치하지 않는다. 날짜 문자열의 현지 timezone 해석에 의존하지 않는다. numeric timestamp 단위·분해능·범위를 capability fixture로 확인한다.

상대 timeout은 이후 벽시계 역행에 의해 재충전되지 않고, 절대 상한은 submit/commit 지연으로 이미 끝난 권한이 잠깐 열리는 것을 막는다. 두 조건 중 하나라도 불일치하면 다음 allow branch로 간다. dual guard가 없는 backend에서 strict-expiry capability를 긍정하지 않는다. Windows/macOS는 F_09에서 같은 상한을 보장하는 native monotonic/UTC 방법을 구현한다.

U는 ‘NTP 사용 중’ boolean이 아니다. 측정 근거, sync age, 추정 drift/slew, trust source와 holdover budget을 기록한다. 기본 허용 오차 목표는 2초이며 환경별 검수값을 고정한다. 허용 오차 밖 wall-clock step을 감지하면 새 grant를 중단하고 임시 허용을 quarantine projection으로 제거한다. 임의 root 시계 조작·VM 전체 일시정지/복원·무제한 OS 정지까지 실시간 보장을 주장하지 않는다. 운영 suspend/hibernate는 비활성화하고 VM snapshot restore는 quarantine/re-enrollment 조건이다.

TTL 재계산은 설치·재설치·rollback 때마다 원래 E로부터 감산한다. read-back의 감소한 timeout을 새 full lease로 reset하지 않는다. clock trust가 없는 재부팅에서는 임시 allow를 복원하지 않는다. 이미 살아 있는 kernel token은 daemon이 죽어도 refresh 없이 종료해야 한다.

## 9. 관리 bootstrap과 소유권 인수

초기 설치는 observe-only다. 다음 항목을 확인하기 전 업무망의 default policy를 변경하지 않는다: 관리 인터페이스·관리 endpoint·controller/signing endpoint·route·IP family·DNS/time dependency·기존 manager·OOB 경로·target identity.

BootstrapManifest는 root 소유의 서명된 설치 객체이며 다음을 담는다.

- scope의 namespace/host identity와 관리 interface·고정 주소.
- 관리 수신의 정확한 source CIDR + destination IP + protocol/port. 기본값은 열어 두지 않음.
- agent가 controller로 시작하는 연결의 정확한 목적지 IP/port와 그 응답.
- 운영에 필요한 제한 loopback, NDP/ARP 경계, 승인된 DNS/time/bootstrap endpoint. 이름만 적고 ANY egress를 만들지 않음.
- 정상 설치 실패 때 사용할 OOB runbook과 로컬 quarantine artifact hash.

기존 manager를 ‘발견했으니 중지’하지 않는다. 관리자 인수 절차에서 명시적으로 scope 소유권을 이전하고 기존 설정을 별도 보관한다. managed table 이외의 타 table은 수정하지 않는다. 인수 시 old policy보다 넓어지는 bootstrap은 그 차분까지 승인받는다.

첫 보호 전환은 baseline B + 업무 default drop을 같은 transaction으로 설치한다. 관리 observer가 **새 TCP 연결**을 만들고 새로운 nonce challenge를 회수해야 한다. 살아 있던 SSH/HTTP keepalive 성공은 통과 증거가 아니다. observer는 target과 다른 프로세스·연결 지점이며 Team에서는 별도 호스트다. target이 스스로 성공 JSON을 만들게 하지 않는다.

boot service는 data interface 활성화/forwarding/일반 workload 시작 전에 durable baseline과 default drop을 설치해야 한다. ordering만 선언하고 실제 boot packet capture를 하지 않은 상태는 검수 실패다. distro/network manager마다 필요한 initramfs/systemd ordering을 설치 프로필에 고정한다. 보호를 설치할 수 없으면 workload/forwarding 활성화를 막고 OOB 복구 상태로 남는다.

## 10. 단일 writer·epoch·generation

authority는 target별 증가 generation을 영속 할당한다. target enforcer는 `(authority_epoch, highest_accepted_generation)`과 grant content hash를 durable하게 보관한다. generation은 정규 10진 u64 문자열이고 overflow는 중단/관리자 epoch 교체 절차이며 wrap-around가 아니다.

- 낮은 epoch/generation은 REPLAY다.
- 같은 epoch/generation + 같은 grant hash는 idempotent 조회이며 저장된 결과만 반환한다.
- 같은 epoch/generation + 다른 hash는 CONFLICT다.
- 새 epoch는 기존 trust root의 승인된 epoch-transition 또는 OOB 재등록만 수용한다. DB row 하나를 바꾸어 만들지 않는다.
- 최고 generation은 prepare의 durable acceptance 시 소비된다. 그 적용이 실패해도 번호를 재사용하지 않는다.

로컬 enforcer 하나가 scope lock을 가진다. watchdog·agent·회수·confirm도 동일한 직렬화 journal/CAS 경계를 사용한다. controller의 DB lock만으로 늦게 도착한 로컬 writer를 막았다고 주장하지 않는다. Linux의 외부 root 변경은 이 위협 경계에서 완전히 막을 수 없으므로 ownership monitor/read-back drift로 중지·경보한다.

## 11. journal과 적용 상태 machine

journal은 append-only framed records + checksum + sequence와 원자 checkpoint를 쓴다. 비밀키는 journal에 쓰지 않는다. directory/file 소유권을 고정하고 file sync뿐 아니라 최초 파일/rename의 parent directory sync까지 구현한다. checksum은 저장소 손상 검출이며 root 공격자에 대한 진위 증명은 아니다. truncated tail은 마지막 valid frame까지 복구하되 transaction 결과를 추측하지 않는다.

필수 record는 accepted grant·hash·epoch/generation, old StateIR/artifact, candidate artifact, installation manifest, tombstone watermark, rollback authority, confirm deadline, watchdog armed acknowledgement, commit submitted, commit/read-back 결과, probe 결과, confirm/recovery CAS 결과다. durable journal에 필요한 공간을 확보할 수 없으면 write 전에 거절한다.

```text
RECEIVED -> PREPARED -> APPLYING -> VERIFYING -> ACTIVE
                    |             |             (확정 이후에도 expiry/revoke 가능)
                    +---- UNKNOWN +---- ROLLING_BACK -> ROLLED_BACK
                                             \----> DEGRADED
```

prepare는 old baseline을 재조회하고 모든 hash/grant/time/fencing을 재검사한다. prepared만으로 ACTIVE를 반환하지 않는다. watchdog을 먼저 arm하고 durable ACK를 받은 뒤 한 kernel transaction으로 rules·tokens·revision 표식을 전환한다. Linux에서 table delete/create가 필요하면 **하나의 batch 안에서** 하며, 두 번의 nft invocation 사이에 table을 없애지 않는다. counters/handles의 보존은 보안 의미보다 우선하지 않는다.

nft executable은 설치 시 검증한 절대 경로의 정해진 binary다. argument array와 길이 제한 JSON stdin만 전달한다. shell, include, user-provided native expression, arbitrary executable path를 허용하지 않는다. stderr/stdout/실행시간을 제한한다. process timeout 후 kernel write의 결과는 UNKNOWN이다.

ACTIVE 조건은 actual semantic read-back, 필요한 양성·음성 probe, 새 관리 연결 probe, 같은 generation/plan/artifact에 대한 서명된 confirm의 durable 저장이다. probe 실패 시 ACTIVE를 잠깐 표시했다가 고치지 않는다. confirm deadline은 `min(applied_at + confirm_timeout, confirm_not_after)`다. 설치 지연 때문에 확인할 시간이 남지 않았으면 새 적용을 시작하지 않는다.

## 12. UNKNOWN 재조정과 취소

UNKNOWN에서는 target 충돌 write와 quota 환급을 중지한다. 조회·read-back·허가된 복구·보안 회수는 가능하되 같은 local fence 아래에서 직렬화한다. 재시도는 같은 idempotency key/grant를 조회하는 것이며 새 generation을 임의로 만들어 중복 적용하지 않는다.

| 실제 관측 | 처리 |
|---|---|
| old artifact와 일치, candidate 적용 증거 없음 | 미적용 receipt. generation 소비는 유지; 새 계획은 현재 old baseline에서 만듦 |
| candidate와 일치, confirm 기한 전 | VERIFYING 재개, 새 probe와 적법한 confirm 필요 |
| candidate와 일치, confirm 기한 후 | 승인된 복구 projection 실행 |
| 허가된 rollback projection과 일치 | ROLLED_BACK receipt 재구성, 복구 CAS/journal 확인 |
| neither/혼합/알 수 없는 표현식 | DEGRADED, quarantine/OOB; 자동 overwrite 금지 |

사용자 cancel은 검증/compile/queue 작업을 중지할 수 있다. prepare 전 취소는 미적용으로 확정한다. commit을 제출한 이후 cancel은 미적용을 뜻하지 않는다. 결과를 먼저 관측하고 적용됐으면 별도 회수/승인된 복구를 요청한다. 작업 timeout도 lease TTL을 늘리지 않는다.

authentically revoked lease는 tombstone을 fsync한 뒤 제거한다. 제거 전 crash면 재시작 때 tombstone을 우선 반영하고 격리를 유지한다. tombstone 생성 전에 회수 완료를 답하지 않는다. 연결 안 된 target의 즉시 회수를 보장하지 않으며 `revocation_pending`·last seen·원래 expires_at의 잔여 상한을 표시한다. 같은 흐름을 다른 lease가 허용하면 회수 receipt에 residual authorization을 기재한다.

## 13. watchdog CAS와 rollback projection

watchdog은 별도 서비스/프로세스로 controller·주 agent의 장애와 독립적으로 작동한다. native kernel 전체/OS가 멈춘 경우까지 독립이라고 주장하지 않는다. watcher identity는 `(scope, operation_id, epoch, generation, candidate_hash)`다.

confirm과 timeout 복구는 동일 durable compare-and-swap를 사용한다. 현재 상태가 예상 candidate/generation인지 검사하고 `VERIFYING -> CONFIRMED` 또는 `VERIFYING -> RECOVERY_CLAIMED` 중 하나만 성공한다. 오래된 watchdog이 늦게 깨어났을 때 current generation/hash가 다르면 아무 정책도 쓰지 않고 stale 이벤트를 남긴다. rollback은 high-water generation을 감소시키지 않는다. 같은 generation 아래 recovery substate와 별도의 actual projection hash를 기록한다.

복구 후보는 다음 순서로 만든다.

1. grant가 승인한 previous StateIR를 가져온다.
2. 현재 시각에 이미 종료된 allow, 로컬/authority에서 확인된 철회 revision, 해지된 binding의 allow를 제거한다.
3. 승인된 recovery profile이 유지하도록 한 candidate/current deny를 합친다.
4. 보존된 allow에도 현재 lifetime·token·deadline binding을 새로 적용한다.
5. 결과 허용 집합이 `rollback_authority.scope_bound_hash`가 가리키는 승인된 범위 이내인지 확인한다.
6. authority deadline과 예상 current generation/hash CAS를 확인하고 원자 적용한 뒤 다시 관측한다.

기본 `preserve-current-restrictions`는 새로운 deny를 rollback이라는 이름으로 지우지 않는다. deny 삭제를 포함하는 가용성 복구가 필요하면 그 Δ+를 계획 단계에서 명시 승인한 별도 profile만 가능하다. 권한이 없거나 기간이 끝났으면 임의 previous raw ruleset을 복원하지 않는다. 설치 때 승인된 quarantine authority에 따라 baseline B + business drop으로 축소하고 DEGRADED로 표시한다. quarantine은 업무 deny의 차단 효과를 약화하지 않지만 업무 통신을 끊을 수 있다.

최신 generation과 맞지 않는 rollback은 시도하지 않는다. 새로운 권한의 영향을 되돌린다고 TCP 세션/이미 전달된 데이터/외부 DB transaction을 복원한다고 표현하지 않는다.

## 14. 재시작·DB restore·키 교체

프로세스 재시작은 먼저 journal/high-water/boot identity를 읽고 actual kernel state를 관측한다. 같은 boot에서 정상 kernel state가 남아 있으면 token TTL을 refresh하지 않는다. 확인할 수 있는 만료/회수를 먼저 적용한다. 재부팅에서는 signed B와 default drop부터 설치하고 신뢰 시각·authority 현재 상태·tombstone reconciliation을 마친 뒤 새 승인된 recovery/install 명령으로만 임시 allow를 재구성한다.

controller DB가 과거 backup으로 돌아가면 read-only reconcile 모드다. target의 최고 generation과 서명된 receipt보다 낮은 상태를 강제로 쓰지 않는다. authority 원장 backup도 독립적으로 검사한다. authority/target high-water를 잃은 경우 ‘0부터 시작’하지 말고 epoch 교체·재등록·기존 권한 격리 절차를 사용한다.

signing key 교체는 trust registry의 유효기간/철회와 epoch 전이 정책으로 처리한다. key ID 문자열, 이전 DB의 approved boolean, 오래된 Git review만으로 새 grant를 발급하지 않는다. offline target의 이미 설치된 권한은 원래 짧은 만료가 상한이며 완전한 즉시 remote revoke라고 주장하지 않는다.

## 15. 구현 완료의 판단과 확장 금지선

F_07의 kernel/driver/extension 실험과 failure receipts가 있어야 해당 backend를 `lab-verified`로 올린다. unit test·모의 adapter·문서 생성·CI skip는 실제 집행 증거가 아니다. `supported`는 지원 OS/kernel/build matrix, 설치·업그레이드·복구 drill, 장기운영·보안 검토와 maintainer를 추가로 요구한다.

NAT는 pre/post translation tuple, reply, ICMP, hairpin, checksum·state 수명 동등성 시험 후 새 프로필로 도입한다. XDP는 nft보다 앞의 drop 최적화로 시작하며 XDP_PASS를 최종 허용으로 취급하지 않는다. inline IPS는 queue absence/full/crash 동작과 기본 firewall 유지 시험이 필요하다. HA는 fencing·split-brain·정책/lease/conntrack 동기화·failover clock 계약을 통과해야 한다. FQDN은 sealed resolution snapshot·TTL·재승인·비결정성 계약, bridge는 부팅 전 격리·L2 loop·ARP/NDP·재시작 시험이 필요하다. 이 확장들을 enum에 적었다는 이유로 활성화하지 않는다.

## 16. 확인한 공식 근거와 설계 선택 구분

본 명세의 union 의미·singleton token·dual guard·CAS·resource limits는 프로젝트의 설계 결정이며 이미 실증된 제품 기능이라는 인용이 아니다. native syntax와 OS 제약은 구현 시 고정 버전 문서와 실제 capability test로 다시 확인한다.

- [nftables 공식 manual](https://netfilter.org/projects/nftables/manpage.html): conntrack original/reply 표현, absolute time, named set·timeout, hook/priority, JSON/check, table 생존 조건의 확인 근거.
- [Linux conntrack sysctl 문서](https://docs.kernel.org/networking/nf_conntrack-sysctl.html): TCP loose pickup·checksum·reassembly 관련 설정의 확인 근거.
- [nftables 원자 규칙 교체](https://wiki.nftables.org/wiki-nftables/index.php/Atomic_rule_replacement): 단일 batch transaction 경계의 근거.
- [RFC 6980](https://www.rfc-editor.org/rfc/rfc6980): IPv6 Neighbor Discovery fragment 제한의 근거.
- [Apple TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api): macOS 배포 제품에 PF를 backend API로 삼지 않는 근거. Network Extension qualification은 F_09에서 별도 정의한다.
