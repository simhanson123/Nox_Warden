# 멀티플랫폼 설치 및 집행 명세

**F-2.0 · 2026-10-30 · R15/R16 필수**

## 1. 지원의 의미

Windows·macOS·Linux에 각각 네이티브 프로그램을 설치하며, 해당 머신의 통신을 그 OS에서 집행한다. Windows/macOS에 Linux VM을 띄워 그 안의 통신만 필터링하고 호스트 보호라고 부르지 않는다. 같은 관리 대시보드, CLI, API, 권한 의미, 감사 증거를 공유한다. macOS Server라는 단종 제품이 아니라 현재 macOS 머신의 서버 운영을 대상으로 한다. [Apple 안내](https://support.apple.com/en-us/101601)

| 초기 필수 검수 조합 | 관리/집행 | 패키지 |
|---|---|---|
| Ubuntu 24.04 LTS x86_64, ARM64 | 공통 코어 + nftables | deb, portable archive |
| Debian 12 x86_64 | 공통 코어 + nftables | deb |
| Rocky Linux 9 x86_64 | 공통 코어 + nftables | rpm |
| Windows Server 2022/2025 x64 | 공통 코어 + WFP callout | 서명된 MSI, CLI zip |
| Windows 11 x64 | 공통 코어 + WFP callout | 같은 MSI의 별도 검수 |
| macOS 14/15/26 Apple Silicon | 공통 코어 + Network Extension | notarized app/pkg, CLI archive |
| macOS 14/15 Intel | 공통 코어 + Network Extension | universal 또는 별도 x86_64 artifact |

이 표는 제품 개발의 목표 검수 조합이다. 현재 supported라는 실측 선언이 아니다. OS 보안 지원이 끝난 조합은 출시 시 재검토하고 문서와 CI matrix를 함께 수정한다. Windows ARM64, 추가 Linux 배포판, 향후 macOS 버전은 같은 suite를 통과한 뒤 추가한다. 패키지 매니저 등록(winget/Homebrew/apt/rpm repo)은 검증된 native artifact를 참조하는 별도 유통 경로이며 최초 설치의 필수 조건이 아니다.

## 2. 공통 backend 계약

backend 식별자는 `nftables`, `windows_wfp`, `macos_network_extension`이다. OS는 `linux`, `windows`, `macos`이다. F_확장계약_스키마.json의 capability/target 객체를 wire 정본으로 사용한다.

| 연산 | 입력/출력 | 필수 성질 |
|---|---|---|
| Capabilities | OS/build/CPU/backend/version, 지원 기능·증거 digest | supported/unsupported/unverified 및 이유, boot마다 재관측 |
| Compile | canonical full candidate, capability hash → artifact/hash | 같은 입력·버전이면 같은 portable artifact; syscall handle은 hash 밖 |
| Prepare | signed grant, expected baseline/epoch/generation | 권한·time·quota·hash 확인, 임의 명령 없음 |
| Apply | 검증된 artifact → applied/unknown | 단일 target 배타 writer, atomic generation publish |
| Readback | target → observed canonical state/hash | DB 캐시와 실제 OS 상태를 구분 |
| Confirm | operation/generation/hash와 probe 증거 | durable CAS, 다른 작업 confirm 금지 |
| Revoke | exact policy/revision + 새로운 승인된 상태 | 기존 TCP/UDP에도 현재 P(t), 비동기 결과 관측 |
| Recover | 복구 권한 + 최신 철회·만료·deny 정보 | 과거 규칙을 무조건 restore하지 않음 |

`common-host-v1`은 로컬 inbound/outbound를 다룬다. routed/bridge/NAT 등 unsupported profile 요청은 422로 거절한다. capability hash가 plan 작성 후 바뀌면 재계획한다. install success만으로 capabilities를 supported로 설정하지 않는다.

## 3. 공통 패킷 의미와 시계

모든 backend는 `허용 = 현재 유효한 allow의 합집합 - 현재 적용되는 deny`를 구현한다. deny는 검토기한이 지났다는 이유로 사라지지 않는다. 기존 연결도 현재 정책을 따른다. 프로세스 신원은 API 신원과 다르며 PID 하나는 workload 신원으로 인정하지 않는다.

매패킷/동등한 재판정 지점에서 정규 tuple·family·direction·interface·현재 epoch/generation·allow expiry를 검사한다. 성능용 flow cache가 있어도 generation 변경과 expiry를 우회하지 않는다. 절대 UTC의 보수적 상한과 재시작 불연속을 다루는 monotonic lease budget을 함께 사용한다. executor 종료·control 단절·suspend/resume·reboot 각각에서 더 넓게 열리지 않는지 시험한다. VM snapshot rollback과 관리자/root의 신뢰 기반 변조는 보호 범위 밖이며 복원 시 재등록/새 epoch가 필요하다.

패킷은 NIC/GSO/GRO/TSO/reassembly/layer별로 관측 지점이 다르다. 이미 허용되어 외부 NIC로 전달된 바이트를 되돌리는 보장은 하지 않는다. 테스트는 backend가 정책을 판정한 시점과 양쪽 endpoint의 실제 전달을 함께 기록한다. 임의 허용 유예를 넣어 늦은 차단을 PASS로 처리하지 않는다.

## 4. Linux backend

F_04의 nftables lowering를 사용한다. 제품 소유 `inet` table/chain만 관리하고 전체 ruleset flush를 금지한다. kernel set timeout과 절대시각 guard의 지원 여부를 실제 probe한다. systemd 서비스와 root/CAP_NET_ADMIN executor, 비특권 controller, ACL된 Unix socket을 분리한다. nft batch 적용과 readback canonicalization을 구현한다. firewalld/ufw/docker가 소유한 rule과 우선순위를 탐지하고 명시적 관리 모드 없이 덮어쓰지 않는다.

Host 프로필은 INPUT/OUTPUT, routed는 FORWARD다. 네트워크 namespace 데모와 실호스트 설치 시험을 둘 다 수행한다. 관리 인터페이스 정책, IPv6 NDP/ICMP, DHCP/DNS 부트스트랩은 문서화한 최소 baseline으로만 허용하고 `established,related accept`를 전체 우회 경로로 넣지 않는다.

## 5. Windows backend

공통 Rust 서비스는 Windows Service로 실행한다. Service SID 및 ACL로 DB·키·named pipe를 분리한다. service와 작은 WDK callout driver 사이의 IOCTL은 version/length/hash/epoch/generation을 검증하고 사용자 supplied pointer·arbitrary memory·arbitrary kernel command를 금지한다. signed portable decision image를 service가 검증하고 driver가 bounds/epoch/generation/time를 다시 검사한다.

WFP provider/sublayer/filter를 제품 GUID로 소유한다. ALE connect/receive-accept에서 최초 연결과 app identity를 수집하되, 이것만으로 기존 연결의 만료를 구현했다고 보지 않는다. transport/packet 또는 필요한 stream layer callout에서 현재 decision image와 deadline을 적용한다. IPv4/IPv6 양쪽, loopback, UDP, ICMP, IPsec/offload, fragment/reassembly의 hook coverage를 fixture로 입증한다. 정해진 layer에서 보이지 않는 metadata는 추정하지 않고 capability를 제한한다.

WFP transaction은 filter 집합의 변경에 사용한다. driver decision image는 immutable double buffer와 atomic generation pointer로 교체하고 기존 reader가 해제될 때까지 옛 image를 보유한다. 서로 다른 WFP layer와 image 교체를 하나의 원자 연산이라고 주장하지 않는다. 확대 과정은 conservative guard → 필터 준비 → image publish → readback → guard 완화 순서로, 축소는 restrictive guard를 먼저 설치한다. 어느 단계나 실패하면 더 좁은 중간 상태를 유지하고 UNKNOWN을 관측한다.

dynamic WFP session은 프로세스 종료 시 객체가 삭제된다. 따라서 이것만으로 기본 차단을 보장할 수 없다. 보호 scope에 persistent callout filters와 boot-time guard를 두고 allow가 사라졌을 때 차단이 남아야 한다. callout 미등록 시 block 동작을 활용하는 설계지만 필수 hook 및 BFE 전환에서 실제 확인해야 한다. `PERMIT_IF_CALLOUT_UNREGISTERED`로 보호 경계를 우회하지 않는다. BFE 시작/중단, service crash/hang, driver load 실패 및 재부팅을 별도 시험한다. [Microsoft 객체 수명](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management), [WFP 동작](https://learn.microsoft.com/en-us/windows/win32/fwp/basic-operation)

타 보안 제품의 deny를 우회하는 hard permit/권한 제거를 사용하지 않는다. 제품 내부 allow는 외부 deny에 의해 여전히 차단될 수 있으며 UI는 이를 관측 결과로 표시한다. Defender Firewall을 자동으로 끄지 않는다. 제품 소유 scope에서 배타 집행·충돌 검증이 실패하면 protection state를 degraded/unsupported로 표시한다.

driver 서명·WDK SDK·출시 인증 요구는 Windows 대상별 공식 절차로 검수한다. 테스트 서명 driver는 격리 VM에서만 사용한다. 사용자에게 Secure Boot를 끄게 하는 것을 정식 설치 절차로 삼지 않는다. MSI에는 서비스 등록·업그레이드·복구·제거·서명 확인과 재부팅 필요 여부를 명시한다.

## 6. macOS backend

macOS 제품은 Swift host app + Network Extension **system extension** + 공통 Rust core로 구성한다. system extension은 로그인 사용자 수명에 묶이지 않는 서버 실행 경로다. 패킷 판정은 `NEFilterPacketProvider`를 기본으로 하고, app/flow 신원에 필요한 경우 `NEFilterDataProvider`를 함께 사용한다. provider마다 보이는 metadata를 별도로 선언하며 서로 다른 callback의 연관을 근거 없이 확정하지 않는다. [Apple 배포 조건](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment), [Apple content filtering 설명](https://developer.apple.com/videos/play/wwdc2025/234/)

공통 evaluator는 C ABI의 제한된 immutable buffer로 연결한다. callback에서 외부 네트워크/DB/LLM을 기다리지 않는다. 검증된 정책 snapshot을 교체하고 callback마다 generation·deadline을 확인한다. 전체 flow에 무기한 allow verdict를 캐시하여 lease 만료를 우회하지 않는다. packet/flow coverage가 충분하지 않은 프로토콜·interface는 unsupported로 표시한다.

host app와 provider IPC는 code-signing identity/audit token으로 peer를 확인한 XPC 또는 검증된 app-group 경로를 사용한다. controller가 extension의 raw 명령을 실행할 수 없도록 한다. entitlement, Developer ID signing, notarization, 사용자 또는 MDM system extension/filter 승인 상태를 설치 진단 화면에 노출한다. 서명키는 저장소·일반 Cloud task에 넣지 않는다.

PF(`/dev/pf`, `pfctl`)는 production fallback으로 사용하지 않는다. Apple은 PF를 널리 배포하는 제품의 안정된 API로 보지 않고 Network Extension 이전을 안내한다. 관리자용 PF 실험 성공을 macOS 제품 지원 증거로 사용하지 않는다. [TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api)

**불확실성을 숨기지 않는 출시 조건:** 이 문서는 extension 종료/강제종료/OS 부팅 초기/업데이트/로그아웃/절전 시 macOS가 자동 fail-closed한다는 검증되지 않은 보장을 하지 않는다. M04M에서 서명된 provider를 실제 기기에서 시험하고, 보호 scope의 트래픽이 새 허용 없이 통과하면 해당 strict profile은 FAIL이다. 그 경우 타이머나 PF로 조용히 대체하지 않는다. 지원되는 Apple API 안에서 보완하거나 정확한 제약을 드러낸 제한 프로필의 별도 결정을 받아야 한다. 3OS full support release는 필수 보장을 충족하기 전 완료할 수 없다.

Mac mini 등 headless 운용은 최초 승인/MDM 등록을 마친 뒤 사용한다. 사람의 승인 없이 모든 macOS에 무인 설치된다고 약속하지 않는다. 서명된 pkg는 app·service·extension을 배치하며 activation pending 상태를 installation failure와 구분한다. 업데이트는 extension 교체와 정책 유지/차단을 검증한다. AirDrop, Continuity, Xcode device networking, Internet Sharing 충돌 시험을 포함한다.

## 7. 3OS 공통 인수 묶음

| 시험 ID | 실행/관측 | 필수 결과 |
|---|---|---|
| OS01 | 깨끗한 OS에 설치, 재부팅, 서비스 등록 | 직접 실행·서명 검증·권한 분리, inactive를 protected라 표시하지 않음 |
| OS02 | 같은 fixture의 새 TCP/UDP·IPv4/IPv6 | reference evaluator와 동일 허용/차단 |
| OS03 | 연결 유지 중 allow 만료 및 deny 추가 | 만료 이후 새 데이터 판정 차단, 다른 유효 allow는 유지 |
| OS04 | controller/executor kill·hang·단절 | 신규 확대 중지, 만료/보호 scope 우회 없음 |
| OS05 | reboot·suspend/resume·시간 불확실 | 과거 allow 부활 없음, fresh proof 없으면 deny |
| OS06 | updater/installer 중간 crash | idempotent 복구, 타 방화벽 설정 보존 |
| OS07 | IPv6·ICMP·fragment·loopback·offload | 문서화되지 않은 우회 없음; unsupported는 admission reject |
| OS08 | 타 보안 제품 동시 설치 | 충돌 감지, 타 deny 우회·전체 disable 없음 |
| OS09 | readback와 실제 probe 불일치 | UNKNOWN/DEGRADED, ACTIVE 금지 |
| OS10 | signed installer 정상 제거/retain-data | 자기 소유 객체만 제거·재설치 안전 |

실행 보고서는 commit, OS full build, architecture, kernel/WDK/SDK/provider version, signature 상태, test topology, fixture hashes, times, packet capture/counter hashes, PASS/FAIL/SKIP와 이유를 포함한다. mock/simulator/교차 컴파일은 이 시험을 대신하지 않는다. 클라우드 Linux 작업에서 Windows kernel 또는 macOS extension을 검증했다고 주장하지 않는다.
