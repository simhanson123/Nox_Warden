# 최종 개발 명세 패키지 — 시작 안내

**F-2.0 · 2026-10-30**

이 묶음은 Codex Cloud에서 구현을 시작할 수 있도록 최종 설계, API·데이터 계약, 저장소·동시성, OS별 집행, UI·다국어, 보안감사, 설치·운영, 시험과 작업 순서를 연결한 **Markdown 중심 개발 명세**다. 실행 가능한 제품이나 검증된 OS installer는 아직 아니다.

최종 방향은 **세 OS 네이티브 설치 + 공통 정책/감사 + Apache-2.0 + 선택적 통계 + 자발적 후원**이다. 기존 양쪽 설계의 근거는 F_기준자료에 보존했고, F-2.0 변경표가 이전 Linux 한정 범위를 대체한다. 프로젝트 이름은 Warden 계열 검토 중이며 `Nox`는 밤이라는 이미지에서 붙인 선택적 조어 요소일 뿐 필수 접두어가 아니다.

## 기계 계약과 재사용 파일

- [내부 통신 schema](F_내부통신_스키마.json), [합성 조회 메시지](F_내부통신_예제.json): 공용 REST와 분리된 등록·집행 채널 계약.

## Codex Cloud에 전달

1. `python F_명세_검증기.py --root .`로 문서/계약 검사한다. Python의 jsonschema가 필요하다.
2. `python F_저장소_내보내기.py --destination ../firewall-repository`로 **빈 디렉터리**에 저장소 형태의 사본을 만든다.
3. 실제 사용할 이름의 GitHub 저장소에 내용을 올리고 Codex Cloud 환경을 준비한다. 이 패키지는 자동으로 저장소를 만들거나 게시하지 않는다.
4. [시작 프롬프트](F_Codex_시작프롬프트.txt)를 사용해 M00부터 진행한다.

F_ 접두어는 전달 산출물에 유지한다. GitHub/Codex 인식에 필요한 `AGENTS.md`, `LICENSE`, `README.md`, `SKILL.md` 등은 내보낸 사본에서 표준 이름으로 배치한다. 원본 이름을 임의로 모두 바꾸지 않는다. 모든 상세 문서는 내보낸 저장소의 `docs/specs`에 함께 들어가므로 로컬 D: 경로나 이 대화를 알아야 개발할 수 있는 구조가 아니다.

## 아직 완료되지 않은 것

native firewall 구현, crypto/DB/driver 실험, 각 OS 보안 보장 검수, 7개 클라우드 실제 배포, 설치 패키지·npm publication, 전체 UI 번역, 공개 이름·상표 확인, Sponsors 활성화와 소개글은 개발/출시 단계의 작업이다. 특히 shared WordPress hosting의 권한 제한과 macOS extension 장애 동작을 숨기지 않는다. 이 패키지의 PASS는 **명세 산출물 검사**이며 실제 제품 지원 인증이 아니다.
