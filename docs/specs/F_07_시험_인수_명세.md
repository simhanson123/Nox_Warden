# F_07 시험·인수 개발 명세

**규격 F-2.0 · 실행해야 할 시험 계약 · 아래 표는 실행 결과가 아니다**

이 문서는 구현자가 만들 test fixture, 환경, 관측값, 통과 기준을 고정한다. 기존 F-1.0 문서/참조검증기의 통과 결과를 새 runtime의 통과로 재사용하지 않는다. 최종 제품 완료는 Linux·Windows Server·macOS의 직접 설치와 공통 호스트 방화벽 전체 흐름을 모두 검수한 상태다. Linux routed 기능은 추가 프로필로 독립 검수한다.

실제 release receipt에는 각 사례를 `passed`, `failed`, `not_run`, `unsupported`, `inconclusive` 중 하나로 기록한다. 인프라가 없어 실행하지 못한 시험은 `not_run`이다. skip/권한 없음/도구 없음/모의 adapter 성공을 passed로 변환하지 않는다. 필수 사례의 not_run/unsupported/inconclusive가 하나라도 있으면 해당 지원 등급으로 승격하지 않는다.

## 1. 실행 계층과 환경

| 계층 | 실행 장소 | 반드시 확인할 것 |
|---|---|---|
| L0 계약·순수 함수 | Codex Cloud·일반 contributor machine | schema, reference evaluator, compiler, state model. 특권 불필요 |
| L1 서비스 통합 | 격리 container/VM의 비특권 프로세스 | SQLite/PostgreSQL, authority, API, MCP, UI, journal fake executor |
| L2 Linux kernel | 폐기 가능한 Linux VM 안의 namespace/실제 NIC profile | CAP_NET_ADMIN/필요한 CAP_NET_RAW, nft·conntrack·module·sysctl·route 실제 결과 |
| L3 Windows | 폐기 가능한 Windows Server VM/별도 서명 qualification 장비 | 설치기, WFP callout, driver loading, boot filter, existing flow, failure |
| L4 macOS | 지원 macOS의 폐기 가능한 VM 또는 전용 시험 Mac | 서명/entitlement/system extension 승인, NE packet provider, 장애 시 OS 동작 |
| L5 운영 검수 | 실제 지원 설치 topology와 별도 observer/OOB | upgrade, reboot, rollback, 관리 연결, 30일 pilot·지원 책임 |

**Codex Cloud에 Linux라는 이유만으로 CAP_NET_ADMIN, nested VM, Windows/macOS, 서명키, entitlement가 있다고 가정하지 않는다.** test runner는 환경을 탐지하고 부족한 조건을 machine-readable reason으로 보고한다. 임의 host firewall·개발자 PC의 네트워크를 건드리는 테스트는 실행하지 않는다. L2 이상은 처음 만든 disposable environment에서만 실행하고 삭제 대상을 workspace ID와 대조한다.

특권 runner에는 운영 비밀/실망 credentials를 넣지 않는다. untrusted PR 코드를 장기 공유 self-hosted runner의 root로 실행하지 않는다. 격리 VM을 한 작업마다 생성하고 폐기한다. 서명 release job과 공격 fixture job의 자격증명을 분리한다.

## 2. 필수 테스트 산출물 구조

구현 저장소에는 다음 책임을 가진 경로를 만든다. 실행 가능한 구현을 만들기 전에는 명령 성공을 예시 receipt로 조작하지 않는다.

```text
tests/contracts/       canonical valid/invalid wire objects 및 golden hashes
tests/semantic/        reference evaluator, table fixtures, property seeds
tests/compiler/        RuleIR 및 native JSON golden, origin mapping, budget tests
tests/model/           authority/target/watchdog/cancel/restore transition models
tests/services/        API·DB·outbox·quota·auth·PBOM integration
tests/kernel/linux/    disposable netns·VM packet/failure harness
tests/native/windows/  WFP/driver/installer/boot qualification harness
tests/native/macos/    Network Extension/installer/boot qualification harness
tests/mcp/             protocol transport·도구·auth·두 client 상호운용
tests/ui/              요청→승인→적용→경로→감사 실제서비스 E2E
tests/security/        parser fuzz·권한경계·서명·supply-chain negative cases
tests/receipts/        receipt schema와 공개 합성 예제(운영 증적 금지)
```

test-case ID는 아래 표의 ID를 유지한다. 테스트를 합치거나 나눠도 receipt에서 원래 의무에 대한 coverage가 보여야 한다. 삭제한 시험을 같은 이름의 빈 test로 대체하지 않는다.

## 3. 공통 합성 fixture

### 3.1 고정 시각과 주소

순수 의미 시험의 기준 시각 `T0=2030-01-01T00:00:00Z`다. 이는 고정 test clock이며 실행 머신의 실제 시각으로 사용하지 않는다. kernel 시험은 trusted test clock의 실제 시작 T0를 기록하고 동일 상대 간격으로 변환한다. 운영 호스트 wall clock을 2030년으로 변경하지 않는다.

| 이름 | IPv4 | IPv6 | 역할 |
|---|---|---|---|
| client A | 10.77.1.10/24 | fd77:1::10/64 | 정상 요청자, original source |
| client B | 10.77.1.11/24 | fd77:1::11/64 | 다른 principal/workload와 주소 확대 반례 |
| gateway left | 10.77.1.1/24 | fd77:1::1/64 | `lan0` |
| gateway right | 10.77.2.1/24 | fd77:2::1/64 | `lan1` |
| service S | 10.77.2.20/24 | fd77:2::20/64 | TCP/UDP 5432, TCP 8443 시험 서비스 |
| management observer | 10.77.3.30/24 | fd77:3::30/64 | 별도 `mgmt0`, fresh connection probe |
| target management | 10.77.3.1/24 | fd77:3::1/64 | 합성 관리 listener 9443 |

namespaces는 `fwtest-<run-id>-client`, `-gw`, `-svc`, `-mgmt`처럼 구분한다. 기본 packet lab은 client/gateway/service의 3 namespace이며, 배포 관리 검수는 네 번째 observer를 추가한다. 실제 source interface 명칭은 artifact에 매핑해 기록한다. 외부 인터넷·실제 사내 주소를 fixture로 쓰지 않는다.

Linux routed 경로는 `A -> lan0/gateway/lan1 -> S`이며 양쪽의 default/static return route가 gateway를 향한다. NAT·bridge·offload·automatic helpers·타 manager는 꺼져 있음을 inventory로 증명한다. PMTU는 service 앞의 추가 router namespace에서 MTU를 낮춰 remote ICMP 오류를 만들고, gateway 자신의 작은 egress MTU에서 local 오류도 따로 만든다.

host 프로필은 시험 OS target의 로컬 service와 외부 peer 두 방향으로 구성한다. INPUT/OUTPUT 각각 original/reply를 시험한다. Windows/macOS 테스트를 Linux namespace adapter로 대체하지 않는다. macOS VM에 필요한 extension 배포 권한이 없으면 별도 전용 Mac receipt가 필요하다.

### 3.2 정책 세트

| ID | action / scope | 수명 |
|---|---|---|
| A1 | allow A→S TCP 5432, lan0→lan1 | `[T0,T0+12s)` |
| A2 | allow A→S TCP 5432, lan0→lan1 | `[T0,T0+30s)` |
| A3 | allow A/B→S TCP 8443, lan0→lan1 | `[T0,T0+30s)` |

property 시험은 최소 10,000개 고정 seed의 작은 상태를 생성한다. 단순 동일 코드 두 번 호출을 differential test라고 부르지 않는다. reference evaluator는 interval/집합 모델로, compiler test interpreter는 RuleIR의 분기 실행으로 독립 구현한다. 모든 random failure는 seed·축소 counterexample를 남긴다.

필수 properties: deny 추가는 permit을 늘리지 않음, allow 삭제는 permit을 늘리지 않음, allow 순열 불변, 중복 허용의 idempotent 의미, 미래 권한 사전활성화 없음, revoked revision 부활 없음, protocol/family 분리, artifact determinism, request patch가 untouched policies/B를 보존함. 잘못된 ‘deny 과대근사면 안전’ property를 만들지 않는다. Δ+·Δ-는 실제 의미에 대해 검사한다.

compiler golden에는 JSON 구문뿐 아니라 모든 allow branch의 token+deadline, deny-before-allow, exact original/reply mapping, 금지 native statement 부재, RuleOriginMap completeness가 포함된다. golden 변경은 사람이 의미 변경과 함께 검토한다.

## 6. 실제 패킷 인수 시험

각 사례는 IPv4/IPv6 및 지원되는 host input/output에서 실행한다. Linux forward는 별도 matrix다. packet마다 sequence/nonce, 송신·방화벽 전후·수신 시각을 기록한다. 수신 application byte count와 packet capture, rule counter를 함께 확인한다. counter만 올라갔다고 endpoint 도달을 증명하지 않는다.

| ID | 절차 | 기대 패킷/관측 |
|---|---|---|
| K01 | B0만 설치, A→S TCP/UDP/echo | 업무 기본 drop, B0 새 관리 접속은 성공 |
| K02 | A1 TCP handshake+연속 sequence 전송 | 유효 기간 original/reply 양방향 수신, unrelated source/port 실패 |
| K03 | A1 만료 직전 연결 유지, daemon 종료 | 종료 상한 뒤 sequence 수신 없음; conntrack entry 잔존 자체는 실패 아님 |
| K04 | A1+A2, A1 만료 | TCP stream 계속 수신, A2 종료 뒤 신규·기존 모두 drop |
| K05 | A2 stream 중 D1 원자 추가 | commit 뒤 평가된 original/reply 모두 drop; 사용자 conntrack cleanup 기다리지 않음 |
| K06 | A3 broad→A-only 축소 | B의 열린 stream이 commit 뒤 drop; stale mark/cache 우회 없음 |
| K07 | TCP5432만 allow, UDP5432/다른 family/잘못된 iface 전송 | 모두 drop; U1 추가 시 UDP만 별도 허용 |
| K08 | TCP unsolicited ACK/SYNACK/RST, conntrack loose 설정 변조 | 신규 권한 성립 안 됨; 필수 sysctl mismatch면 capability/health 실패 |
| K09 | UDP original/reply 및 reverse-new | 원본 request에 속한 reply만 current union으로 허용 |
| K10 | echo E4/E6, unsolicited reply/type/code 변조 | 정확한 request/reply와 유효시간만 허용 |
| K11 | 정상 parent의 remote/local PMTU 오류 | 유효 parent에서 전달·MTU 조정; parent 만료/deny 후 차단 |
| K12 | RELATED helper data·위조 embedded tuple·redirect | 지원 오류 subset 밖은 drop |
| K13 | NDP NS/NA/DAD·허가 router RA | 등록 baseline 범위에서 통신 시작; hoplimit≠255/다른 RA source/fragmented ND drop |
| K14 | 정상/순서변경/overlap/tiny IPv4·IPv6 fragment | 지원된 정상 reassembly만 원래 정책 적용, 파싱불가를 allow로 바꾸지 않음 |
| K15 | IPv6 extension chain/atomic fragment/비지원 L4 | parser coverage 결과 명시; 미지원은 drop·unsupported capability |
| K16 | wrong source on lan0/lan1, source binding 재사용 | anti-spoof drop, 다른 workload의 잔존 lease 재사용 안 됨 |
| K17 | 2개 정책 수정 중 continuous negative probe | Linux batch는 old 또는 new 전체 의미만 관찰. 다른 OS의 명시된 guard 단계는 F_04/F_09의 더 좁은 허용 상한 이내; 중간 allow-all/deny 우회 없음 |
| K18 | 타 table/counters 설치 후 managed apply/rollback | 소유 table 외 변화 없음; flush ruleset 실행 흔적 없음 |
| K19 | 다른 base chain/flowtable/offload/NAT 활성화 | preflight reject 또는 profile unsupported, 몰래 지원으로 표시하지 않음 |
| K20 | token 물리 GC 지연, expired element dump 존재 | membership으로 허용 안 됨; GC 존재 여부와 논리 만료 구별 |

TTL 시험에서 `expires_at` 이후에 도착한 패킷만 보고 실패/성공을 정하지 않는다. 이미 만료 전에 허용돼 네트워크 queue에 있던 패킷은 늦게 도착할 수 있다. 방화벽 평가시점/양쪽 capture의 clock uncertainty를 보고하고 **만료 후 새로 주입한 식별 가능한 패킷**이 허용됐는지 판정한다. 경계 양쪽 1ms/10ms/100ms/1s probe를 사용하되 측정 정밀도가 그보다 낮으면 해당 결과를 inconclusive로 둔다. 정확한 경계는 L0 clock model과 native timer unit 시험도 결합한다.

| F09 | rollback authority 만료/범위 초과 | 임의 확대복구 없음, 승인된 B+drop quarantine 및 DEGRADED |

| F18 | target journal/high-water 손실·VM snapshot restore | 자동 0 reset 금지, quarantine/re-enrollment 요구 |
| F19 | grant 재전송/동일generation 다른hash/이전epoch | 같은내용 결과조회, 다른내용 conflict, 이전epoch replay |

| F21 | revoke tombstone fsync 직후 crash | 재시작 시 tombstone 우선, 권한 부활 없이 제거·관측 |
| F22 | target 단절 후 root delegation 철회 | 신규grant 중단, 기존은 pending+TTL상한 표시, 즉시회수완료 주장 없음 |
| F23 | management old keepalive만 살아 있고 새 연결 차단 | probe 실패, ACTIVE 불가, 지정 복구 수행 |
| F24 | manager 외부 root가 rule/set/route 변경 | drift 관측, 충돌 write 중지, 실제 상태와 desired 차이를 노출 |

kill 시험은 service 전체 종료와 개별 controller/agent/enforcer/watchdog 종료를 구별한다. kernel 자체 crash·NIC loss는 가용성 장애이며 daemon crash와 같은 fail-close 입증으로 재사용하지 않는다. OS pause/suspend 지원을 주장하려면 pause 중 timer·재개 전 격리·snapshot rollback을 별도 검수한다.

state model은 최소 두 operations, 두 generations, 한 confirm, 한 watchdog, 한 revoke, commit unknown을 interleave한다. 검증 invariant는 no-overpermit, no-resurrection, generation monotonicity, single-final-state, unknown quota retention, stale-writer rejection이다. 모의 model의 통과는 실제 kernel transaction/fsync 동작 증명을 대신하지 않는다.

지원 matrix는 OS 이름만 적지 않는다. 배포판/OS edition·version/build·architecture·kernel/API/SDK/runtime·설치 형식·서명 유형·profile·승인 단계·시험 receipt를 기록한다. Windows 데스크톱의 실험을 Windows Server 검수로, macOS PF 실험을 Network Extension 검수로 대체하지 않는다.

## 11. 성능·자원·장기 실행

성능 목표는 F_01의 F-2.0 기준을 따르며 미측정 상태는 숫자에 `target`을 붙인다. F-1.0 수치와 조건이 다르면 최신 F_01 조건으로 측정한다. 성공률·안전성을 낮춰 목표를 맞추지 않는다. 운영지원은 실제 지원 OS/build마다 측정한다.

- 정책 0/100/1,000개에서 compiler time, native apply/read-back, rules/set/kernel memory, controller/agent RSS를 별도 측정한다.
- 64/512/1500-byte 패킷, IPv4/IPv6, TCP/UDP, 허용/차단, 동시 세션 수, TTL 겹침, PPS·throughput·p50/p95/p99 latency와 CPU를 보고한다.
- no-firewall baseline과 기능없는 default-drop/단순allow baseline을 구별한다. NIC/offload/CPU/VM host/MTU·도구버전·warmup·반복 횟수를 고정한다.
- 일반 read API는 100req/s 기준 p95 300ms, UI list p95 500ms, 단일 target 1,000 policy/5,000 branch에서 계획 p95 2초가 F-2.0 초기 목표다. apply+read-back p95 2초 목표는 별도로 측정한다. 승인/외부모델/probe 시간을 측정에서 빼면 그 제외를 명시한다.
- 7일 bounded load 후 RSS/FD/thread/task/channel/DB/outbox/kernel conntrack/set memory의 plateau와 slope를 본다. 평균만으로 누수 회귀를 감추지 않는다.
- conntrack/set/DB/disk 포화·로그 폭주·취소 폭주에서 신규 작업을 429/명시오류로 제한하고 기존 expiry/default deny를 유지한다. 가용성 저하는 실제 수치로 보고한다.

PR branch protection에 required workflow가 실제 등록되어 있어야 한다. CI UI에 job이 green이어도 그 job 내부의 필수 kernel tests가 skip이면 G2는 통과하지 않는다. 이를 위해 aggregate gate가 receipt 목록과 profile별 필수 ID를 대조한다. 플랫폼별 preview 공개는 가능하지만 상태/미완료 플랫폼을 명시하며 전체제품 완료 문구를 쓰지 않는다.

확장 NAT/HA/bridge/XDP/inline IPS/FQDN/vendor write는 F_04/F_09와 설계결정의 RFC exit gate를 별도 실행한다. `unsupported`가 core 필수 기능으로 확산되도록 조용히 scope를 줄이지 않는다. 이미 약속한 세 OS common-host 기능의 실패는 해결할 결함 또는 미완료다.

## 13. 실행 receipt와 증거의 최소 형식

각 run은 immutable run ID와 다음 내용을 기록한다. receipt schema는 구현 저장소에 제공하고 CI aggregate가 검증한다.

```text
spec_version, suite_version, run_id, started_at, finished_at
source_commit, source_tree_hash, dirty_worktree, build_digest
platform/edition/version/build/arch, backend/version, capability_hash
runner_isolation, privilege_checks, clock_source/uncertainty, boot_id
profile, topology_hash, fixture_hash, artifact_hash, installation_hash
case_results[{id, status, reason_code, started_at, finished_at, evidence_hashes}]
required_case_ids, missing_required_ids, aggregate_status
raw_log_hashes, packet_capture_hashes, native_dump_hashes, screenshot_hashes
observer_identity, signature_or_authenticated_provenance, limitations
```

packet capture/log는 합성 데이터만 공개하고 token·key·실사용자 주소·payload가 섞이지 않게 redaction을 검증한다. redaction 전후 hash 관계와 보관 위치의 접근 범위를 명시한다. 파일 hash가 있다고 그 내용의 사실성·시험 성공이 증명되는 것은 아니다. 신뢰할 수 있는 실행 주체·topology·tool versions와 원시 증거를 함께 보존한다.

원시 capture가 없거나 테스트 서비스가 실행되지 않은 상태에서 ‘패킷이 안 도착함’을 차단 성공으로 판정하지 않는다. negative probe는 동일 fixture의 positive-control 경로가 살아 있음을 확인해야 한다. 결과 변경 시 이전 receipt를 덮어쓰지 않는다. 재실행은 새 run ID이며 원래 실패를 연결한다.

## 14. 최종 인수 서명 조건

출시 담당자는 선택한 지원 matrix의 모든 필수 case와 UI trace를 확인하고, 미지원 확장·시각/네트워크/신원 한계를 명시한다. 설치·요청·승인·실제집행·경로·감사·만료·회수·복구의 연결이 세 OS에서 각각 있어야 한다. 운영 secret 없이 다른 maintainer가 동일 합성 lab과 릴리스 빌드를 재현할 수 있어야 한다.

문서가 완성됐거나 모의시험이 통과했다는 이유로 kernel/driver/extension 기능을 완료라고 기록하지 않는다. 이 명세의 최종 산출물은 앞으로 무엇을 구현·검수해야 하는지에 대한 완결된 기준이며, 실제 제품의 상태는 실행 receipt로 갱신한다.
